## 1. 最重要的收获：**两个判断错误**（别再犯）

这两个错误各值一个数量级，而且都**不在实现里，在判断里**。

### 错误一：目标漂移 —— 把"相似度"当成"质量"

**我花了几周优化"和真品的 trit 一致率"**，而它**不是质量指标**：

```
trit 一致率 90%  →  PPL 1290（差真品 309 倍）
```

**⇒ 同一模型上，`--scale ls`（最小化权重误差）26.52 vs `--scale ref`（匹配真品 trit 模式）197.39**。
**dense 上同样：438 vs 1290。**

**⇒ 判据只能是 PPL + 生成实测。相似度可以完全背离质量。**

### 错误二：保护范围搞反 —— 以为是"位置"，其实是"通路"

**我保护过 router、embedding、`ssm_out`**，都没用。
**实际敏感的是 GDN 递推路径的**输入**：**

```
(空)                     PPL = 26.52
attn_qkv 单独              PPL = 14.27
attn_qkv + attn_gate      PPL = 11.06
attn_qkv + attn_output    PPL = 12.59
GDN 三类                   PPL =  8.87
再 + 全注意力三类(实六类)    PPL =  6.20
```

**⇒ 贡献是**可加**的** ⇒ **机制是**GDN 的递推状态把它所有输入上的量化误差逐 token 累加** ⇒
**每个未保护的输入都贡献漂移。**

**用户的原话命中：**"思维链前几句通顺、随后开始循环"** —— 这就是递推漂移的特征。**

## 5. 环境坑（全部踩过，且大多**不报错**）

| 坑 | 表现 | 对策 |
|---|---|---|
| **正则里的反斜杠** | 打包成功但**一个张量没保住**，体积和不加时相同 | **写进脚本文件**；或改用无反斜杠写法 |
| **多步命令被 PS 拆** | 编译跑了、推送没跑 → 假阴性 | **一步一命令** |
| **`echo` 写 base64** | 写出 **0 字节** | 用 `printf %s` |
| **并发按核数** | 三个 12 GB 模型在 28 GB 内存上 **OOM** | **按内存算并发** |
| **`pkill -f`** | 杀掉自己的 shell | 用 `[p]attern` |
| **`dsw.py put`** | Jupyter contents API **404** | 只走 base64-over-shell（单文件 ≲20 KB） |
| **大日志无换行** | `grep` 抓不到 | `tr -cd '[:print:]\n' \| tail -c N` |
| **NAS 有配额** | 文件系统报 979T 空闲，但写 12 GB 失败 | 把可重下的权重放 `/tmp` |
| **实例号会变** | API 全 404 | **先怀疑实例号，别怀疑方法** |
